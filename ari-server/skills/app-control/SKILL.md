# 앱 제어 (App Control)

## 사용 지침

1. **앱 탐색**: 대상 앱 ID를 모르거나 연결 상태가 불확실한 경우에만 `list_apps`를 호출하십시오. 이미 컨텍스트에 있다면 생략합니다.
2. **기능 파악 (필수)**: `control_app`을 호출하기 전에 해당 앱의 **실제 스킬 문서**에 있는 명령어만 사용해야 합니다.
   - 시스템 프롬프트에 대상 앱의 SKILL이 이미 주입되어 있거나(Preloaded), 같은 대화에서 이미 `read_skill`로 읽었다면 다시 읽지 마십시오.
   - 둘 중 어느 것도 해당되지 않으면 **반드시** `read_skill`로 대상 앱의 SKILL을 먼저 읽으십시오.
   - **명령어 이름을 추측하지 마십시오.** "자동매매 시작"처럼 자연어에서 연상되는 명령(`START_AUTO_TRADING`, `START_TRADING`, `RUN_STRATEGY` 등)은 대부분 존재하지 않습니다. 스킬 문서에 정확히 기재된 이름만 사용하십시오.
   - 보낸 명령이 `Unknown event` 에러로 돌아오면 재시도로 다른 이름을 찍지 말고, 즉시 스킬을 다시 확인하거나 사용자에게 실제 지원 명령으로 무엇을 원하는지 질문하십시오.
3. **명령 전송 및 실행**: 앱 제어는 `control_app` 하나로 처리합니다.
   - 실행 중이든 꺼져 있든 `control_app(app, command, params?)` 호출. 꺼져 있으면 자동으로 실행 후 연결 대기.
   - 종료는 `control_app(app, "SHUTDOWN")` — 앱이 스스로 정리 후 종료.
   - 이미 꺼진 앱에 SHUTDOWN을 보내도 안전 (no-op).
4. **상태 확인**: 앱 전용 스킬에 상태 조회 명령이 없을 때만 `read_app_state`를 사용하십시오. 스킬에 GET/READ 류 명령이 있다면 그쪽을 우선하십시오.
5. **주의 사항**: 앱이 응답하지 않거나 자동 실행 타임아웃 시, 사용자에게 상황을 보고하고 재시도 여부를 확인하십시오. 프리즈된 앱은 이 스킬로 죽이지 못하므로 필요시 사용자에게 안내하십시오.
6. **응답 작성**: 사용자 응답에 내부 프로토콜 명령어(예: `ADD_WORK_SESSION`, `GET_STATE`, `SHUTDOWN` 등)를 그대로 노출하지 마십시오. 결과는 자연어로 설명합니다.
